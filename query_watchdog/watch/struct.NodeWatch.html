Expand description

Checker of one watched node: follow, retries and sweep, one request at a time.

Source

async fn retry_step(&mut self) -> Result<usize>

RetryQueue::new at now; while RETRY_BUDGET from the step start has time left: recovery, the representative when recovery was empty at the step start (a result that found_present sets recovery = ChunkQueue::confirmed(set)), recovery again, due not-found rows, then due failed rows. Recovery and the representative go first so that not-found rows, due every minute, cannot use the whole budget; returns requests sent.

A healing attempt after the node’s own route answered 404: a 200 from route means the node fetched and stored the object (Ok, a local miss). Any other result keeps the 404, since a node that cannot serve the object through its peers cannot serve clients either; the cause goes to the DEBUG log.
